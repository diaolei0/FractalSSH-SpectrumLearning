# v12 release audit

Release: `v12-paper-operator-hierarchy-2026-09-13-r1`

## Correctness checks completed locally

- All Python sources compile.
- `SELF_TEST_V12.py` passes in two separate processes.
- Operator process imports NumPy/SciPy only; training process does not import SciPy, sklearn or matplotlib.
- D4 rotations/reflections preserve the v12 K1/K2/K3/eta2 feature tensors on representative formal masks.
- Formal `b5_F0024_N24`: two-step paths are present; K2 and K3 OC-BULK0 blocks cancel to numerical zero and the cache records the `>K3` class.
- Formal `b7_F0003_N17`: K2 OC-BULK0 is numerically zero while K3 is nonzero and the cache records the `K3` class.
- 120 formal geometry families were feature-benchmarked consecutively with no shape/nonfinite failures.

## Real-database integration test

A 9-family mini database generated by the official v7 physics builder was used for an end-to-end test:

```text
operator audit/cache
-> production data loader
-> forward
-> loss
-> backward
-> optimizer step
-> train
-> resume
-> six checkpoint load/test/export paths
```

All paths completed successfully.  A production-size default model (`d_model=128`, 3 spectral blocks, 40 latents) also passed forward/loss/backward on a real family.

## Numerical invariants observed

- predicted energy chiral max error: exactly 0 in the smoke checks;
- monotonic violations: 0;
- projector probability row-sum error: ~2.4e-7;
- gradients finite;
- operator features finite.

## Scope not executed here

The complete 816-family, 140-epoch CUDA training cannot be executed in this environment because the full `states/` database and the user's CUDA machine are not available here.  Therefore this release is code-path verified, not a claim of final v12 performance.
